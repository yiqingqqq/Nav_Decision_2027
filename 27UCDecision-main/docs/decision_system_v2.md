# RMUC 2026 哨兵决策系统方案

## 推荐结论

采用“安全监督 + 世界模型 + Utility AI 战术选择 + 行为树执行 + Nav2 运动规划”的混合架构。
现有 BehaviorTree.CPP 继续作为可解释、可打断的执行层，不再承担全部战术判断。

## 分层结构

1. **感知与通信层**：接收裁判系统、视觉目标、雷达、多机通信、定位和 Nav2 状态。
2. **世界模型**：将不同频率、不同时间戳的数据整理成统一快照，并维护数据可信度和超时状态。
3. **战术地图**：在静态栅格地图上叠加敌方威胁、队友占用、交战收益、路径风险和禁行区域。
4. **Utility AI**：以 5-10Hz 对候选任务评分，例如补给、基地防守、前哨站防守、中心巡逻、支援和追击。
5. **行为树执行层**：执行选中的任务，负责导航、云台模式、射击许可、超时、重试和失败恢复。
6. **安全监督层**：独立处理低血量、定位失效、通信超时、底盘卡死、禁区和急停，优先级最高。

## Utility AI 实现形式

每个候选任务由多个归一化特征评分：

```text
score(task) = base
            + w_value * tactical_value
            - w_path * normalized_path_cost
            - w_threat * expected_damage
            + w_team * team_support
            + w_phase * phase_fit
            + hysteresis_if_current_task
```

硬约束先过滤任务，例如定位失效时禁止远距离进攻、弹量不足时禁止追击、目标数据超时后禁止按旧坐标
继续行动。评分只在安全且可达的候选任务之间比较。

为避免哨兵在两个任务之间频繁跳变，需要同时使用：

- 当前任务滞回加分；
- 最短任务保持时间；
- 新任务超过当前任务一定分差才切换；
- 补给、急撤等紧急事件可绕过保持时间。

## ROS 2 节点建议

```text
rm_world_model       聚合并校验比赛状态
rm_tactical_map      生成语义区、威胁和路径代价
rm_task_selector     Utility AI 评分并发布 TacticalGoal
rm_behavior_tree     执行 TacticalGoal
Nav2                 全局规划、局部避障和控制
rm_safety_supervisor 独立发布中止/撤退/急停指令
```

`TacticalGoal` 至少包含任务类型、目标语义区、目标 ID、优先级、生成时间、有效期和选择原因。调试日志应
记录所有候选任务的分数与被过滤原因，以便赛后回放调权。

## 其它可选方案

### 参数化行为树

只改造现有行为树，将阈值和航点全部配置化。实现最快、稳定性高，但复杂局势下树会快速膨胀。适合第
一个可运行里程碑，不适合作为最终战术层。

### GOAP/HTN + 行为树

由 GOAP 或 HTN 规划“补给 -> 占点 -> 支援”等多步任务，行为树执行每一步。适合资源和事件链较明确
的长期策略，但需要维护动作前置条件、效果和失败回滚。可在 Utility AI 稳定后用于上层战略规划。

### MCTS/MPC

在有限时间窗内预测双方运动与收益，适合局部交战和拦截点选择。计算量和对模型准确性的要求较高，
建议只用于局部模块，不替代整套决策系统。

### 强化学习

不建议首版采用端到端强化学习直接输出底盘动作。更稳妥的用法是离线学习 Utility 权重、预测交战收益
或提供候选任务排序，并始终保留行为树与安全监督兜底。

## 落地顺序

1. 完成语义地图、红蓝方变换和现场地图标定。
2. 建立世界模型，补齐消息时间戳、超时和可信度。
3. 将现有行为树拆成补给、防守、巡逻、进攻、脱困等可复用子树。
4. 实现可记录评分明细的 Utility AI，先用人工权重。
5. 接入仿真/rosbag 回放，统计任务切换率、路径成功率、存活时间和有效交战时间。
6. 数据充足后再加入 GOAP、MCTS 或离线学习模块。
